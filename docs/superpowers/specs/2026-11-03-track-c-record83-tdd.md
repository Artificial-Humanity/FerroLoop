## Part 1 — What counts as a proof (normative)

A whole-slice bound for one admitted automated execution slice is PROVEN only if BOTH a finite total token bound AND a finite total cost bound over the complete slice are DEDUCED from quantities fixed BEFORE dispatch (a dollar cap alone never establishes tokens, a token cap alone never establishes cost). The proof is a reviewed proof RECORD, not a vendor-wide bit: it pins binary hash/version, model, auth/billing mode, transport, config digest, scope and each enforcing knob. Any unsupported change to a pinned input invalidates the proof. A passing live transcript corroborates the pre-dispatch proof obligations; it cannot by itself establish a universal upper bound. Hidden/reasoning/cache/tool-context tokens count wherever billed, with conservative prices and rounding. A proof is established by exactly one of:

- **P-A Vendor-enforced cap + epsilon.** The vendor runtime checks a configured cap between steps and stops the slice there. A between-steps check never yields a bare cap: the proven bound is **cap + epsilon**, where epsilon is one maximal step priced P-B style (context_window input at the uncached rate + max output). Proof obligation: vendor documentation or schema naming the cap's scope, plus a live conformance run where a deliberately tiny cap stops a long task AND the observed overshoot beyond the cap is <= epsilon (a run that merely stays under the cap proves nothing).
- **P-B Arithmetic cap.** (max model steps) x (max input tokens per step + max output tokens per step) x price, where every factor is set by us before dispatch and enforced by the vendor or the transport. Proof obligation: each factor has a named enforcing knob; per-step input is bounded by an ENFORCED context limit (not by VendorDescriptor.default_context_window at vendor.rs:80, which is a descriptive default, not an enforcement knob); price comes from the proof's named accounting unit and authoritative billing contract (see Accounting units below). The step count must include subagent steps, retries, auto-compaction/summarisation and vendor-internal planner calls — an uncounted class voids the factor.
- **P-C Per-request admission decomposition.** The controller itself issues every model request of the slice, admits each with its own reservation, AND the slice carries a fixed finite envelope (max request count) fixed before dispatch; summing individually admitted requests is not a finite whole-slice proof if unlimited requests can follow. Proof obligation: every internal request is intercepted (the vendor cannot make un-admitted model requests inside one turn).

**Accounting units.** Every proof names its accounting unit and authoritative billing contract. Virtual API-equivalent subscription value (#221) is a distinct reporting metric; it is neither a predecessor for nor proof of actual dollar cost, and unknown cost is never replaced by an estimated virtual card. Subscription incremental cost of 0 is acceptable only if proven for the configured plan/path under the Owner's budget semantics; tokens still need their own independent finite bound.

Explicitly NOT proofs (safeguards only, retained): reactive spend checks during streaming (harness.rs:264-295 checks partial_cost > budget at <=1s intervals then kills the process group — overshoot is whatever one in-flight request plus one interval costs, unbounded as a token quantity); timeouts; quota observation; post-hoc reconciliation. Automated admission requires P-A, P-B or P-C per adapter; otherwise the adapter row stays ManualOnly.

Recorded in code (capability truth): the descriptor gains `slice_bounds: Vec<SliceBoundProof>` where each proof is keyed by **(adapter, execution mode, CLI version range)** — a proof for `claude --print` says nothing about the PTY/stream-json path #217 drives. SliceBoundProof { proof_record_id, mode, cli_version_range + binary hash, model, auth/billing mode, config_digest, kind: VendorCap { knob } | Arithmetic { steps_knob, max_out_knob } | PerRequest { max_requests }, accounting_unit, transcript_ref }. The descriptor references reviewed proof records; it never carries a generic vendor-wide proven bit. Admission reads the INSTALLED binary's version at dispatch; no matching proof (wrong mode or version outside the proven range) means Unproven => automated refusal with alert, no prose exceptions. L2 golden tests are the CI tripwire; the runtime version check is the guard.

## Part 2 — Per-adapter proof strategy and expected verdicts (hypotheses for the harness to settle)

- **claude** — P-A candidate. `claude --print --max-budget-usd` exists in help and claude.rs:44-51 already passes budget through for attempts. Open questions: does the cap cover the whole agentic loop incl. subagents/tool steps, is it API-mode only or subscription too, does total_cost_usd in the result envelope ever exceed the cap (overshoot epsilon), does stream-json interactive mode honor it identically?
- **muse** — P-B candidate. `muse exec` exposes `--max-model-steps`, `--max-turns`, `--max-tool-output-bytes` in help. Bound = steps x (context_window + max_output). Must verify step counting includes subagent steps, auto-compaction/summarisation calls and any vendor-internal planner calls (Muse spawns its own subagents; if any of these escape the counter, P-B fails and muse falls to Unproven for automated use). L1/L3 include a case that forces a compaction.
- **codex** — likely Unproven in v1. app-server turn/start admits one turn; internal model/tool steps inside the turn are vendor-driven. P-C fails unless app-server exposes per-request control. Check for max_output_tokens-equivalent per turn (TurnStartParams) plus a step cap in the exported schema; if only output-per-request is cappable with unbounded internal requests, verdict stays ManualOnly. This is an acceptable outcome, not a failure of the harness.
- **antigravity** — likely Unproven. LS cascade steps are vendor-internal; print mode has --print-timeout (time, not tokens). Check cascade step accounting via RevertToCascadeStep surface; otherwise ManualOnly. Borrowed endpoint in any case (no automated work per #217 v4.4).
- **grok** — unknown. Check headless `-p` for output/token caps and whether one -p invocation can loop internally without bound. Until a knob is found and tested: Unproven.
- **API adapters (api.rs)** — P-B CANDIDATE, not proven: output_cap() (api.rs:286 call, :438 body) estimates input as instruction_len/4, which is not a hard token bound. It becomes proven only when the request-input upper bound, all billed output classes and retries are established; until then it is the harness's first test subject, not its reference proof.

## Part 3 — Harness design

Three layers, all behind existing test conventions (unit in-module, subprocess scenarios in tests/, live only behind an explicit env gate, never in CI):

- **L1 Fake-vendor conformance (CI).** Extend the ProcessHarness fake-dialect tests (harness.rs tests already inject scripted usage lines). Fake CLIs emit scripted multi-step usage streams; assertions: reservation is taken atomically before spawn (store CAS per #217 §E), slice bound arithmetic matches descriptor values, refusal path when SliceBoundKind=Unproven (no spawn, alert record written), concurrent admissions against one allocation (exactly one wins the last slice), safeguards still fire (reactive kill path unchanged).
- **L2 Schema/help pinning (CI, no spend).** Golden tests over recorded flag/schema surfaces: `claude --help` budget flag, `muse exec --help` step caps, codex exported JSON-schema field presence. A vendor update that removes a knob turns the adapter's tests red before it silently unbounds a slice (same pattern as #217 U-cell conformance tests).
- **L3 Live experiment (opt-in, owner-run).** The harness must not assume the cap it exists to prove: a candidate cap is UNPROVEN during its own evaluation, so each experiment runs under an explicit Owner experiment allocation (separate from admission budgets), with isolated test credentials/data, no automatic retries or subagents beyond the fixture under test, an outer process deadline and cost alerts. A '$0.05 self-cap' is an aspiration for that first run, not a known safety bound. Normal admissions stay denied throughout. Overrun, missing telemetry or inability to prove are reported as ManualOnly, never retried into compliance. `FL_LIVE_PROOF=1` test binary, one test per adapter, and tasks engineered to exceed it: (a) 'count aloud in separate steps as high as you can' (turns), (b) a task that forces a multi-iteration tool loop, and (c) for muse/claude, a task that forces one subagent spawn — without (b) and (c) the matrix's tool-loop and subagent-counted columns cannot be filled. Record: observed stop behavior, final total tokens/cost from the vendor's own usage output, overshoot vs cap. A reviewed pre-dispatch derivation establishes the proof; L3 only corroborates it. The descriptor PR cites both. Descriptor flip from Unproven is a code PR, never a config change. For P-A, cap + enforced epsilon is reserved atomically BEFORE dispatch for the whole slice (epsilon is only valid if itself enforced per Part 1 and inside the reservation). L3 spends real (tiny) money/tokens: owner-run only, outside CI, budget for the whole matrix stated in the test header.

**Test matrix (per adapter x proof type):** rows claude/muse/codex/antigravity/grok/api; columns: knob exists (L2), arithmetic factors all settable, multi-step stream stays inside bound (L1 fake + L3 live), subagent/tool/internal steps counted (incl. forced compaction), interrupt does not refund spent slice, reservation released only by actuals. Each row is per (mode, version range), not per adapter globally. Each cell: pass/fail/not-applicable with the named test. Fixtures additionally cover: adversarial hidden steps, forks/subagents, resumed histories, retries, prompt growth, cache/reasoning pricing, rounding, concurrent reservations, crash-before-settlement, and descriptor drift (binary/model/config change invalidating a proof at dispatch).

**Exit gate for #83 Part 1:** every adapter row has a recorded verdict (Proven-P-A/B/C with transcript ref, or ManualOnly). Automated paths (auto-restart hydration, scheduled routines, #60 balancing) check the descriptor and refuse per row. No row may read 'assumed'.
