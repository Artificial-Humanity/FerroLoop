# FerroWatch per-agent usage — design

Status: approved by Ferris for issue #495 phase 1, with the storage design below. The issue defines the owner-approved scope; no separate owner review is needed.

## Purpose and scope

Report locally observed token consumption per persona, vendor and model for requested time windows rounded to whole UTC hours. Attribute Antigravity internal conversations to their parent persona; retain counted history after transcript removal. Expose the same data through `fl watch usage`, an Owner-only hub endpoint, and a sortable FerroDeck table. Do not store transcript content. Alerts, budget conversions and balance planning remain out of scope.

## Collection and storage

- A single hub-owned, single-flight collector is the only writer. CLI and API only read durable workspace usage documents, so offline CLI reports work and GET requests never scan transcripts. The first scan reads existing files once; later scans seek from the last complete newline, leaving a partial line for the next scan. Bound bytes, line sizes, files and work per cycle; expose pending/error state instead of silently reporting complete.
- Use a dedicated FerroStore collection, such as `watch_usage_v1`, separate from FerroState's indexed state collections so render and search do not see usage documents. Support the ferro engine only. If `AnyStore::as_ferro()` is unavailable, return an explicit unsupported-backend error for redb; do not silently fall back or report empty usage.
- Keep one document per source (conversation or rollout file). It contains source and session identity, vendor, byte cursor and source generation, parser baseline, hourly buckets keyed by model and UTC hour, and coverage/error state. Each bucket holds input, output, cache-read and cache-write counts, turns, and per-category unavailable flags. Keep undated observations separately marked as such. Parser state includes Codex cumulative totals and a bounded recent Claude message-ID baseline sufficient to handle streamed revisions, including prior counted values and bucket identity where needed. Store only counts, identifiers and diagnostics, never message text, prompts or arbitrary transcript fields.
- Build the next source document in memory and persist the cursor, baseline and buckets together with **one existing atomic single-entry** `FerroStore::put_doc` write. A crash before that write leaves the entire previous document intact; a restart and rescan cannot double-count committed data. Single-flight hub ownership supplies serialization; no cross-process CAS, per-event rows or new usage-store transaction layer is needed. Validate sizes and bounded scan work before writing.
- Identify files by stable file identity as well as path; detect rotation, replacement and truncation and assign a new generation. Retain documents after source deletion. When overlapping or rewritten generations cannot be deduplicated safely from available evidence and bounded parser state, preserve prior counts and mark coverage incomplete rather than silently adding another copy. Handle malformed and incomplete records without persisting raw data or skipping later valid data.
- Store small separate session/conversation mapping documents with persona, parent ID, launch time and provenance, updating them as hosted, route, tombstone or passive identity evidence arrives. Buckets remain attached to their source session; query-time joins resolve mappings and parent chains. Late persona or parent bindings therefore require no count rewrite. Never guess ambiguous identity; preserve unresolved counts as unattributed and guard cycles and missing parents. Count each known subagent launch once from the mapping, not once per usage record; expose unknown launch times separately.

## Vendor semantics

- Antigravity: establish which usage-bearing step kinds represent charged calls from sanitized fixtures and the manual comparison; the existing `PLANNER_RESPONSE` parser only reads latest context and is not proof that other usage-bearing steps can be ignored. Parse event timestamp, model and conversation identity from logs; resolve internal conversation to parent from its message step and metadata independently of usage records. Establish safe event identity across `transcript.jsonl`, `transcript_full.jsonl`, rewinds and repeated records; do not equate a reused step index with the same charged call without evidence. Where bounded state cannot establish safe deduplication, mark incomplete. Verify fixtures and retained 2026-11-08 to 2026-11-10 data against the manual reference.
- Codex: parse rollout `event_msg` / `token_count` `payload.info` fields, tracking cumulative totals and deriving deltas only for new observations; repeated snapshots must not count again. Commit the cumulative baseline with buckets and cursor in the same document. Detect partial resets and model changes; do not treat cumulative snapshots as independent turns or infer turns without evidence. The issue's `/payload/event/usage` pointer is used by Muse `model_completed`, not the Codex parser. Verify actual fields and turn semantics against sanitized fixtures.
- Claude: parse assistant message usage, accounting for multiple streamed entries of one message without duplication and revising the materialized count when a later observation corrects it; input, cache creation, cache read and output are separate fields. Identify model and time from each event. Retain only a bounded recent message baseline; if safe correction is no longer possible, mark coverage incomplete rather than inventing a count.
- Muse: parse `runtime.session` / `model_completed` usage when exposed. Grok: inspect local signal/summary formats; if counts or timestamps are not available, expose no data, not zero. Mark unsupported token categories unavailable rather than inventing numbers.
- Use UTC and half-open windows. For a requested `[since, now)` interval, floor `since` to the hour and ceil `now` to the hour (an already aligned endpoint remains unchanged); report both requested and effective `[start, end)` boundaries. This includes whole boundary buckets and only observations collected so far. Undated observations are reported separately and never silently placed in the window. Count each known subagent launch at its recorded launch time; unknown launch time is separately reported. Historical data deleted before collection cannot be recovered and coverage must say so. Token fields preserve vendor meanings; do not silently add cache counts to input or compare across vendors as identical billing units. Missing model, time or identity is visible as unknown/unattributed, not dropped or fabricated.

## Interfaces

- `fl watch usage [--since 48h] [--by persona|vendor|model] [--json]` reads durable workspace documents locally, even when the hub is offline; only the hub collector scans transcripts. Validate time ranges and grouping; default to 24 hours and persona grouping. Report requested and effective boundaries, source completeness, last successful scan, unavailable categories and unattributed totals.
- `GET /api/v1/usage?since=…&by=…` checks Owner authority explicitly before data access. Accept an absolute timestamp or duration for `since`; return normalized rows, units, requested and effective range, and collection status. Reject malformed input with 400 and peer access with 403; report unsupported redb explicitly. No transcript content is returned.
- Add a sortable usage table to the existing FerroWatch view, using the API's existing visual language and explicit loading, empty, stale and error states. Show input, output, cache read/write, turns and subagents and disclose effective window boundaries. Seven-day per-agent sparkline only if it can be supplied without another costly scan; it is optional in phase 1. Keyboard sorting and responsive layout are required.

## Verification and rollout

Fixture tests for each supported parser, alternate/missing fields, duplicate records and counters, model changes, partial lines, source replacement, late parent/identity binding and deleted transcripts. Test single-flight scheduling, crash before the atomic write, idempotent rescan and restart on ferro, plus explicit redb unsupported behavior; test Owner/peer API authorization, CLI JSON and formatting, and the FerroDeck table. Run the repository verification trio, UI tests/build, and live isolated hub checks with Playwright and Chrome DevTools including console, network and keyboard accessibility; close pages afterwards. Compare the retained Antigravity window with the manual approximately 17.4M input, 1.5M output and 247M cache-read; report effective UTC boundaries, coverage and discrepancy without exposing transcript contents. Never mutate live source transcripts.

## Open implementation checks

Confirm actual source-specific event and turn identities, timestamp fields, rotations, parent-link representation and bounded collection enumeration/query cost. Clarify whether the manual totals use inclusive window endpoints and what retained-conversation coverage is. If a source cannot supply a safe deduplication key or a source format's counters are ambiguous, label its data incomplete rather than claiming exact totals.
