# Model-switch delivery implementation plan

> For agentic workers: use the repository's subagent-dev workflow with per-task independent review.

**Goal:** Make FerroDeck model changes truthful and persistent without sending slash commands as chat turns.

**Spec:** GitHub #463. Use an isolated Codex app-server and mock provider only; never touch live sockets or credentials.

**Evidence:** Codex 0.167.1 experimental `thread/settings/update` changed model and effort, an interrupted subsequent turn recorded both, and thread resume on a fresh isolated server retained them. It requires experimental API opt-in; two completed turns and synchronization with a running TUI remain unproven. Treat Codex as deferred until the latter is proved; do not send `/model` or `/effort` as turns and do not drive its model picker via PTY. A future live switch may build on #528 composer location.

## Task 1 — Hub persistence and per-vendor delivery

- [ ] Add failing endpoint tests: post by a thread UUID updates the persona-keyed hosted record; a simulated persistence failure is surfaced before setting the in-memory override or dispatching anything; a Codex mock app-server receives no turn or slash text; recordless override-only response cannot promise restart persistence.
- [ ] Persist using raw ID, canonical ID and persona in the same lookup as `hosted_record_for`; distinguish missing records from failed writes. Return structured `persisted` (boolean and record id) and `live` (status `applied`, `deferred`, `held`, or `failed`, and mechanism). A busy session or occupied composer is `held`, never `applied`. Retain owner authorization and Antigravity model/effort mapping.
- [ ] Audit route delivery explicitly: Codex and Antigravity are stored/override-only. Grok and Muse's generic operator path may run a headless model turn; never use that fallback for slash commands. Permit live delivery only where the route offers a proven terminal-only path, otherwise report override-only. For Claude, only terminal paste counts as live delivery; never use the peer socket user frame. Terminal paste held for a busy session or occupied composer reports `held`. State the behavior of each Claude route kind in the PR. HostCli and webhook require the same conservative rule. Cover each route kind and fallback with mocks; no real vendor process or socket.
- [ ] Test each method's actual delivery outcome and failure; keep failed persistence from masquerading as success. Verify a hosted restart actually launches with the stored model and effort for Codex and another vendor; where a vendor does not, never claim it applies on restart. Test saved record plus failed live delivery reports persisted and failed. Document per-vendor behavior and the isolated Codex evidence in the PR.

## Task 2 — FerroDeck feedback

- [ ] Derive UI feedback from both structured outcomes: show `Applies on next restart` only when persistence succeeded and restart is verified; distinguish held and failed live delivery. If saved but live delivery fails, retain the saved choice and say so. If no hosted record was saved, explain the choice was not applied and is not persisted. Preserve rollback only for failed persistence/API errors.
- [ ] Add UI tests for delivered, persisted deferred, unpersisted and failed outcomes, including both callback and direct-client paths. Run `npx vitest run` and `npx tsc --noEmit`; record totals.

Each task: failing tests first, implement, focused tests, commit with Felix trailer, independent review/fix loop. Finish with full branch review, `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test --workspace` (disclose #533 if it recurs).
