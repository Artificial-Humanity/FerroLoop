# Model-switch delivery implementation plan

> For agentic workers: use the repository's subagent-dev workflow with per-task independent review.

**Goal:** Make FerroDeck model changes truthful and persistent without sending slash commands as chat turns.

**Spec:** GitHub #463. Use an isolated Codex app-server and mock provider only; never touch live sockets or credentials.

**Evidence:** Codex 0.167.1 experimental `thread/settings/update` changed model and effort, an interrupted subsequent turn recorded both, and thread resume on a fresh isolated server retained them. It requires experimental API opt-in; two completed turns and synchronization with a running TUI remain unproven. Treat Codex as override-only until the latter is proved; do not send `/model` or `/effort` as turns.

## Task 1 — Hub persistence and per-vendor delivery

- [ ] Add failing endpoint tests: post by a thread UUID updates the persona-keyed hosted record; a simulated persistence failure is surfaced before setting the in-memory override or dispatching anything; a Codex mock app-server receives no turn or slash text; recordless override-only response cannot promise restart persistence.
- [ ] Persist using raw ID, canonical ID and persona in the same lookup as `hosted_record_for`; distinguish missing records from failed writes. Include explicit response information about persistence and whether a live change was actually delivered. Retain owner authorization and Antigravity model/effort mapping.
- [ ] Audit route delivery explicitly: Codex and Antigravity are stored/override-only. Grok and Muse's generic operator path may run a headless model turn; never use that fallback for slash commands. Permit live delivery only where the route offers a proven terminal-only path, otherwise report override-only. Claude's peer-socket fallback sends a user frame, so it is not proof of applying a slash command; distinguish live terminal delivery from socket fallback. HostCli and webhook require the same conservative rule. Cover each route kind and fallback with mocks; no real vendor process or socket.
- [ ] Test each method's actual delivery outcome and failure; keep failed persistence from masquerading as success. Document per-vendor behavior and the isolated Codex evidence in the PR.

## Task 2 — FerroDeck feedback

- [ ] When response reports override-only and hosted persistence succeeded, show `Applies on next restart`; if no hosted record was saved, explain the choice was not applied and is not persisted. Do not show a live-success message for a deferred choice. Preserve rollback on API errors.
- [ ] Add UI tests for delivered, persisted deferred, unpersisted and failed outcomes, including both callback and direct-client paths. Run `npx vitest run` and `npx tsc --noEmit`; record totals.

Each task: failing tests first, implement, focused tests, commit with Felix trailer, independent review/fix loop. Finish with full branch review, `cargo fmt --all --check`, `cargo clippy --all-targets -- -D warnings`, and `cargo test --workspace` (disclose #533 if it recurs).
