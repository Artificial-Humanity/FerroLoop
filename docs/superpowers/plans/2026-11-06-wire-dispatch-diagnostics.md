# Wire Dispatch Diagnostics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-dev` to implement this plan task-by-task, with a fresh implementer and the `code-review` review/fix/scoped-review loop per task. Steps use checkbox (`- [ ]`) syntax for tracking. Repository WORKFLOW.md governs execution.

**Goal:** Explain current daemon-lifetime delivery fences through bounded, sanitized Status evidence without changing delivery or suppression.

**Architecture:** Add a bounded observation report to the existing dispatch path, then atomically retain its safe projection when the existing daemon creates a fence. Expose a cloned in-memory snapshot through optional Status data and existing CLI formatting; do not persist diagnostics or add recovery authority.

**Tech Stack:** Rust, serde/serde_json, existing sha2, Unix local sockets, temporary stores and fake transports in tests.

**Spec:** [Approved design snapshot](../specs/2026-11-06-wire-dispatch-diagnostics-design.md), SHA256 `f270fb3352bb828b683804118be9980fb125b1ebc3004f5a29590d4eefd534ee`.

- Lead design selection: Ferris message `urn:uuid:01a1b258-656b-714a-a97f-82b6b53211fb`. The snapshot is preserved verbatim, including its earlier proposal labels; this plan records the later approval. Approval of design is not implementation or rollout GO.
- Source baseline: `44e1bdfc25baff65e6fbbe35d6fad9f83046c66e`. Before execution, compare current main for overlapping Rust/API changes and request review for material differences.
- Preserve existing dispatch outcomes, route-refresh retries, receipt attempts/status, ordering, queue limits, fence lifetimes, ACK semantics, peer behavior and private-socket access. Do not add retry/probe/read/write solely to collect evidence.
- At most128 retained recipient records; each serialized row <=4096 bytes; max4 failure stages retaining the first and decisive final stage; up to2 route observations; separate saturating actual-call and omitted-item counters with saturation flags.
- Normalized recipient only when valid and <=64 bytes; otherwise fixed digest plus invalid marker. Message ID only when <=256 bytes; otherwise digest and omission flag. Do not change the actual delivery/suppression keys.
- New evidence/log fields contain enums, bounded IDs/digests/timestamps/counters only: no body, subject, argv, cwd, paths, CSRF/keys, stdout/stderr, raw errors or panic payloads. Existing routes output is outside this slice and must not be reserialized into diagnostics.
- Registration generation remains null. Route snapshot identity proves neither liveness nor authorization; actual route-dispatch calls are not child-process/emission counts. Missing evidence stays unknown.
- Diagnostics are volatile and observational. Restart loses the snapshot, not proof that restart is safe recovery. No store format/migration/claims/recovery, #360 provenance, Record143, hook/wrapper, host, deployment or live probes.
- A queued `overflowed` flag already suppresses new appends but is not yet a retained recipient fence: the accepted prefix may still drain. Capture its earliest trigger atomically with that existing flag, in the same <=128-row diagnostics budget. Expose observational phase `prefix_draining` versus `retained_fence`; promotion preserves original evidence/time and appends a distinct decisive later Unconfirmed/spawn cause. This is plan-level DTO precision consistent with the approved unchanged-suppression contract, not a new scheduling state or authority. A full diagnostics budget marks only diagnostic omission; it must never set the real overflow_capacity_exhausted flag or create a real fence.

## Review Focus

1. A push succeeds but receipt write or final read fails: report the observed stages without claiming push failed or granting retry (Tasks2–3).
2. Duplicate same-name receipts can produce more than two calls: actual-call counting must remain independent of capped observations (Tasks1–2).
3. Invalid imported names and credential-bearing routes/errors: new evidence and logs remain bounded and secret-free without changing keys (Tasks1–3).
4. Concurrent fencing, ACK, registration and Status: evidence pairs with the existing fence and the first hold survives; no extra lock spans vendor/store/log I/O (Task3).
5. Older/offline daemon capability absence versus supported-empty: retain the distinction in both JSON and human output, without extra Status I/O (Task4).

### Task1: Bounded evidence vocabulary and safe projection

**Files:** Create `crates/wire/src/dispatch_diagnostics.rs`; modify `crates/wire/src/lib.rs`. Tests are in the new module's `#[cfg(test)] mod tests`.

**Interfaces produced:**
- Public serde DTOs `DispatchDiagnostics`, `FenceDiagnostic`, `RouteDispatchObservation`, `FailureStage`, `FenceReason`, `DispatchCallOutcome`; derive Debug/Clone/PartialEq/Eq as applicable. All wire enums use snake_case. Do not expose arbitrary error-string fields.
- `DispatchDiagnostics`: schema_version1, `instance_nonce: Option<String>` encoded as32 lowercase hex characters when available and serialized as null when entropy is unavailable, instance_started_at `At`, scope `daemon_lifetime`, records `Vec<FenceDiagnostic>`, global_capacity_exhausted bool, diagnostics_partial bool, omitted_evidence_total `u64` and saturation flag. Partial means some attempted diagnostic retention was omitted, not a complete list of all holds. Nonce is observational, not authentication; try existing ring randomness once at daemon creation, leave the nonce explicitly unavailable on entropy failure, and preserve existing daemon startup/delivery behavior. Never read randomness in Status.
- `FenceDiagnostic`: safe recipient label/digest, optional bounded trigger ID/digest with omission flag, hold_observed_at `At`, phase (`prefix_draining` or `retained_fence`), first_reason and decisive_reason, bounded failure stages and omitted count/saturation, bounded route observations and omitted count/saturation, `route_dispatch_calls: u64` and saturation flag. Distinguish unknown trigger/route from zero calls. `registration_generation: Option<u64>` serializes null in v1.
- `RouteDispatchObservation`: adapter enum, optional domain-separated SHA256 identity digest, optional `At` route_updated_at and explicit bool, call outcome enum (`unknown`, `returned_ok`, `returned_error`). `Webhook` has adapter identity but no session digest; absent/empty session identity is unknown, not a hash of a socket path.
- Crate-private `DispatchReport::default()`, `record_failure(stage: FailureStage)`, `record_call_started(entry: &RouteEntry) -> Option<usize>`, `record_call_finished(observation_slot: Option<usize>, outcome: DispatchCallOutcome)`, and `FenceDiagnostic::from_report(recipient: &str, message_id: Option<&MessageId>, hold_observed_at: At, phase: SuppressionPhase, reason: FenceReason, report: &DispatchReport) -> Self`. Starting a call increments its counter and records safe route/unknown outcome BEFORE invocation; finishing updates only a retained observation. Thus panic during the call still reports one invocation with unknown outcome.
- FailureStage covers message lookup missing/error, initial receipt read error, transport error, receipt write error/missing, final receipt read error/missing, unresolved receipt status and worker panic. FenceReason additionally distinguishes queue overflow, worker spawn failure and global metadata cap. These are observations, not trusted nonmutation categories.
