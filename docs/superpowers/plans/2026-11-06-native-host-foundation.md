# Native Agent Host Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-dev` to implement this plan task by task, including its per-task `code-review` loop and final whole-branch review. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an authenticated, vendor-neutral `fl-host` daemon that owns pipe children on Linux, macOS, and Windows, without changing live agent routes.

**Architecture:** `fl-host-proto` owns typed messages, bounded framing, platform transport and blocking/async clients. `fl-host` owns the standalone executable, child supervision and session inventory. The hub remains the future vendor-RPC owner and the only component that admits automated vendor turns.

**Tech Stack:** Workspace Rust edition 2024 / Rust 1.98, serde, serde_json, tokio, libc on Unix, windows-sys on Windows. No PTY dependency in this slice.

**Spec:** [Approved Issue #217 source snapshot](../specs/2026-11-03-native-agent-host-design.md), v2 §§1–3 and 7 as amended by v3 §4 and v4.5 §§A, C–F. Read the amendments before implementing the older text.

**Implementation refinements:** This plan is the authoritative implementation contract for the foundation where it tightens the archived spec: endpoint-derived state, mutual nonce authentication instead of a raw-token hello, binary Line framing, separate event connections, bounded writer-coordinated leases, and epoch-guarded signals/kills. These refinements and the creation-time Windows Job refinement below override conflicting older snippets; the approved source snapshot remains archival and unchanged.

## Global Constraints

- This is the pipe-child foundation from PR 1, not the full host or an agent migration. No vendor CLI, inference call, automatic restart, route replacement or live tmux teardown belongs in this branch.
- Later slices add PTYs, full ack/replay, service units and cgroups, the hub SessionController and persistence, Codex, Claude, the remaining adapters, console integration, and finally the migration. Codex precedes Claude per Ferris's latest handoff.
- Keep the host standalone. It must not depend on `fl-cli`, `fl-hub`, `fl-wire`, `fl-exec` or `fl-store`. Neither hub nor wire links a PTY library.
- `fl-host-proto` and `fl-host` compile and run tests on all three operating systems from the first code PR. Windows acceptance includes the real `fl-host.exe`, not merely protocol unit tests.
- Keep `test, clippy, fmt` unchanged. Add `fl-host (macos)` and `fl-host (windows)` jobs. The code PR touches `.github/` and needs owner review under `WORKFLOW.md`. Prepare the complete reviewed PR before requesting that approval. Do not change branch-protection settings.
- Define named bounds in `fl-host-proto`: frame payload 256 KiB after its type byte; logical Line 1 MiB raw bytes plus at most 4 KiB envelope; stdout line 1 MiB; stdin 64 queued lines and 256 KiB including newlines; input operation/progress at most 5 s; stderr tail 64 KiB; sessions 64 by default; subscribers 16; shared stdout backlog 8 MiB per session. The detailed framing, authentication, subscriber and input bounds below are normative.
- Fragment only complete logical Line events in this slice; control messages fit one frame. Preserve raw non-UTF-8 stdout, never deliver an incomplete Line chain, and never truncate pipe output silently. Snapshot fragmentation belongs to the next slice.
- Host events carry `session`, durable `session_epoch` and monotonic per-session `seq`, never `thread_epoch`. A connection-bound `controller_lease` fences every `Send`/future `Write` at the actual stdin writer. Successful takeover acknowledgement is a fence boundary; an atomic generation change alone cannot fence an OS write already pending.
- Unix containment is best effort until the delegated Linux cgroup slice. Windows children are born in a non-inheritable kill-on-close Job and execute only after containment is verified.
- No automated-execution admission ships in this slice. The later controller must enforce the whole-slice token/cost proof and atomic reservations from v4.5 §E. Existing `fl-core::slice_proof` is input to that work, not evidence that a vendor qualifies.
- Work only in isolated worktrees. Every commit uses the machine author and the responsible agent's co-author trailer. The PR author owns the merge after current-head approval and green checks.

## Review Focus

- An unrelated file, symlink, foreign-owned socket or live socket occupies the endpoint: refuse without unlinking it. Under the held exclusive lock, replace only an owned socket whose connect returns `ConnectionRefused`; a second daemon cannot replace the live daemon's token or endpoint.
- A client sends a valid frame length then stalls: handshake and incomplete-frame reads have finite, named deadlines; an idle session with no RPC is not a partially read frame.
- A child floods stderr while stdout is idle: bounded stderr drainage continues without blocking the child or growing memory.
- A session leader exits before its descendants: preserve containment ownership until explicit cleanup; a kill must not touch a sibling session or a reused PID.
- A new controller takes over while old stdin writes are queued or active: queued stale writes return `NotWritten`; resolve or abandon active writes before acknowledging takeover. Abandoned partial input makes the session `Fenced`, preventing input under every lease until kill and respawn.

- `HostEndpoint::discover() -> Result<HostEndpoint, HostError>` resolves `FL_HOST_SOCK` before platform defaults into `UnixPath` or `WindowsPipe` typed variants, with endpoint-derived state as specified below. Authentication material is separate from the public endpoint string; `HostEndpoint`, `HostConfig` and the secret newtype have redacted `Debug` implementations.
- `AsyncHostClient::connect(&HostEndpoint) -> Result<Self, HostError>` completes peer validation and mutual authentication before returning. `request(&mut self, HostRequest) -> Result<HostResponse, HostError>` correlates a nonzero, strictly increasing connection-local u64 request id; refuse exhaustion, reused ids, unknown response ids and duplicate responses. `BlockingHostClient` exposes the same semantics without requiring a caller-owned tokio runtime.
- `events(&HostEndpoint, filter) -> Result<HostEventStream, HostError>` opens its own independently authenticated connection, issues `Events`, and receives one correlated subscription acknowledgement before switching that connection permanently to stream-only mode. Ordinary RPC connections receive only correlated responses; stream connections accept no further RPC or second subscription. Event connection loss does not revoke a lease owned by a separate control connection.
- The listener exports an authenticated async connection over one platform-neutral stream abstraction usable by the daemon. Define its concrete API in `src/transport/mod.rs` in this task; later tasks consume it directly, never duplicate handshake logic.
- Authentication uses `Challenge`, `Hello`, `Proof` and `Welcome` frames only in the handshake state machine below. Authenticated requests in this slice: `Spawn`, `List`, `Kill`, `Events`, `ClaimLease`, `Send`, `Signal`. `SpawnSpec` contains session id, pipe kind, argv, cwd, environment override map and an explicit environment allow-list. PTY requests return typed `Unsupported` until the next slice.
- `ChildState` distinguishes `LeaderExited` from `CleanupComplete`: a leader status never implies descendant cleanup.
- `ClaimLease { session, expected_epoch }` returns a new lease only after Task 3's writer-coordinated takeover. `Send { session, expected_epoch, lease, line }` returns the typed writer outcome below. `Signal { session, expected_epoch, lease, signal }` always needs both epoch and lease; `Kill { session, expected_epoch, lease: Option<_> }` always needs epoch, permits an authenticated operator without a lease, and validates a supplied lease. Future write/resize operations must use the same epoch/lease guard. The host never interprets vendor JSON inside a line.

**Endpoint ownership and publication:**
- Unix `FL_HOST_SOCK` is an absolute full path, not a directory. Reject empty/NUL paths and paths that fail the store's `socket_path_fits` rule (104-byte macOS / 108-byte Linux `sun_path`, including its terminating NUL). macOS defaults to its per-user temporary directory; tests use a short private root under the platform's per-user runtime/temp directory so the full socket path fits.
- Derive Unix `<endpoint>.lock`, `<endpoint>.token` and `<endpoint>.state.json` from that exact endpoint; the state file holds Task 2's durable epochs and Unix survivor records. On Windows, `FL_HOST_SOCK` is a pipe-name suffix: accept ASCII `[A-Za-z0-9._-]` only and reject empty suffixes, `..`, NUL and lengths over 200 characters (backslash/slash are consequently invalid). Normalize ASCII case before constructing the SID-specific full pipe name and hashing it, since pipe names are case-insensitive; also reject a full name above Windows' 256-character limit. Derive mutex and token/state basenames from SHA-256 of that canonical full name, placing files in a private `%LOCALAPPDATA%/FerroLoop/host/` directory. Distinct endpoints never share lock, token, survivor registry or epoch store; aliases of the same endpoint use the same identity.
- Before accessing Unix endpoint/state files, validate the parent with no-follow metadata: it must be a directory, not a symlink, owned by effective uid, and `mode & 0o077 == 0`. Create missing private parents at 0700; refuse existing wrong modes/owners rather than chmod them. Pin the validated parent for relative no-follow file operations; private path components must not be symlinks. Trusted OS ancestors need not themselves be 0700 and may be canonicalized first (for example macOS `/var` to `/private/var`); do not canonicalize away a symlink at the private parent or endpoint. Use the resulting canonical parent plus basename as endpoint identity on both sides. Lock/token/state entries must be owned regular files, no symlinks, mode 0600 and link count one, checked on opened handles; reject unexpected types, owners, modes or link aliases rather than repairing them.
- Acquire the exclusive endpoint lock before publishing a token or mutating socket/state. Hold it throughout daemon lifetime. Under that lock, `lstat` an existing socket: remove only an euid-owned socket after connect returns exactly `ConnectionRefused`, rechecking node identity before unlink. Refuse a live socket, foreign owner, symlink, non-socket or any other connect error without unlinking. Clean shutdown unlinks only the socket inode this daemon bound. Create/bind at 0600 before listen inside the validated private parent.
- Generate a fresh 32-byte token with `getrandom` each daemon start. Unix publication uses a private random temporary file opened `O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC` at 0600, write/sync, then atomic rename under the lock and directory sync; never write-then-chmod. Validate any replaced token entry first. Clients use no-follow open and handle-based owner/type/mode checks, and require exactly 32 bytes. On Windows create the private host directory and token/state/temporary files with the protected current-SID-only DACL in `SECURITY_ATTRIBUTES`, not after writing; random temporary files use `CreateFileW(CREATE_NEW)` and atomic replacement. Client reads use reparse-aware opens and handle-based owner/ACL/type checks; reject reparse points and unexpected ownership/ACLs. Remove a token on clean exit only after checking that it is still the file containing this daemon's token; never delete another daemon's replacement. Compare secrets/proofs in constant time and never log their bytes or proofs.
- Set close-on-exec on the lock, token/state, listener, accepted/client socket and auxiliary FDs. Use atomic CLOEXEC APIs where available; on macOS serialize spawn against any create-plus-`fcntl(FD_CLOEXEC)` window. Only Task 2's explicitly documented supervisor handoff endpoints may survive its exec, with all other copies closed. Windows handles are non-inheritable except the explicit child stdio allow-list.

**Peer validation and authentication:**
- Both sides validate OS peer identity before exchanging any frame. Unix accepts exactly `peer_uid == own_euid`, including own uid 0; a foreign uid 0 is refused like any other foreign uid. Use a pure validator accepting the peer lookup result; errors and unsupported platforms fail closed. Port the store `auth.rs::peer_uid` pattern without linking `fl-store`: Linux `SO_PEERCRED` with exact returned-ucred-length validation; macOS/BSD `getpeereid`; unsupported fallback refuses. Use uid only, never peer pid as authorization.
- Windows reads the current SID from process-token `GetTokenInformation(TokenUser)`, never `USERNAME`. Both sides query the opposite pipe process (`GetNamedPipeServerProcessId` / `GetNamedPipeClientProcessId`) and validate its token user against their own SID using opened process/token handles; lookup/access failure refuses authentication. Client opens with `SECURITY_SQOS_PRESENT | SECURITY_IDENTIFICATION` to prevent server impersonation. Identity validation does not replace the mutual token proof.
- After peer validation, reserve one of at most 32 concurrent unauthenticated slots and start a 5 s total handshake deadline covering all reads/writes. Refuse excess connections without reading a frame. Every pre-auth frame payload is at most 4 KiB, checked before allocation. No ordinary request, session inventory or daemon version is exposed before successful authentication.
- Use fresh, independently random 32-byte server/client nonces `ns`/`nc` per connection; reject `ns == nc`. State order is `Unauth -> Challenge(ns) -> Hello(nc, requested_proto, client_proof) -> Proof(server_proof) -> Welcome -> Ready`. The client must validate the server proof before accepting Welcome. No token bytes cross the wire. Transcript bytes are `endpoint_len:u32be || endpoint_bytes || requested_major:u16be || requested_minor:u16be || ns:[u8;32] || nc:[u8;32]`; endpoint bytes are the canonical Unix path's native bytes or the canonical Windows pipe name's ASCII bytes. Client proof is HMAC-SHA256(token, `fl-host/auth/1/client` || transcript), server proof uses the distinct `fl-host/auth/1/server` domain. Fixed-size proofs and constant-time verification, both nonces, endpoint/protocol binding and role separation prevent replay/reflection; do not reuse the store's proof domains.
- Authenticate proofs before checking protocol compatibility. Only after mutual proof exchange send Welcome with success or typed `IncompatibleProtocol` plus daemon version; a bad token receives no version. An ordinary request before Ready, malformed/out-of-order handshake, or second Hello after Ready closes the connection. Use one handshake implementation for blocking/async clients and daemon.
- Authenticated idle reads are unbounded until the first byte of a frame arrives. From that byte, the complete header and body have one 10 s absolute deadline (not reset per byte); truncated/expired frames close the connection and discard reassembly. RPC and event outbound frame writes have a 5 s absolute deadline. Handshake writes remain within its shorter total deadline.

**Windows named-pipe ownership:**
- `FILE_FLAG_FIRST_PIPE_INSTANCE` on the first instance is the authoritative singleton check across logon sessions; map its `ACCESS_DENIED` to typed already-running refusal without touching the incumbent token/state. An endpoint-derived `Local` mutex is only a fast path. Acquire the authoritative pipe instance before replacing token/state, and keep at least one instance alive until shutdown.
- Every instance is byte mode with `PIPE_REJECT_REMOTE_CLIENTS`, protected DACL `D:P(A;;GA;;;<current process SID>)`, exactly one allow ACE and no inherited ACEs, and `bInheritHandle = FALSE`; do not add a low-integrity SACL. Before handing a connected instance to its handler, pre-create the next standby instance with identical security and `first_pipe_instance(false)`. Keep a listening/connected instance alive during replacement so the pipe name is never released. Clients retry `ERROR_PIPE_BUSY` within a 5 s connection deadline.
- CI inspects `GetSecurityInfo` on real pipe/token handles: protected DACL, exactly the current-SID ACE, no Everyone/Authenticated Users/Network ACE and no inheritance. Unit-test byte mode, non-inheritance, remote rejection and client SQOS options. CI does not prove a real second-user or remote-machine denial; document that limitation in `docs/host-foundation.md`.

**Wire representation and admission:**
- A frame is big-endian `u32 length`, `u8 type`, then payload. `length = 1 + payload.len()`, valid range 1 through `1 + 256 KiB`; handshake payload has its smaller cap. Validate in u64 with checked addition before any allocation or usize cast, including on 32-bit targets. Zero/oversize length or unknown type closes the connection. Control frames contain complete UTF-8 JSON, one message per frame, with no fragmentation; reject oversize controls before sending and after bounded decode.
- Line frames carry raw bytes, never a JSON string/base64: payload begins with fixed header `session_len:u8`, `session:[u8;64]` (ASCII id, zero-padded), `session_epoch:u64`, `seq:u64`, `more:u8` (0/1), integers big-endian, followed by raw line bytes. All fragments repeat the same header identity; each fragment consumes header bytes within the 256 KiB payload cap. `seq` identifies one logical event and advances only for the next event; reject exhaustion rather than wrapping. A Line excludes its terminating LF; an unterminated final stdout tail at EOF is one complete Line. Binary/control characters and non-UTF-8 bytes round-trip unchanged.
- One connection may have only one unfinished Line chain; no other logical event or control frame may interleave. Fragments must have matching `(session, session_epoch, seq)` and valid flags; an inconsistent identity is a protocol error. Empty raw fragments are refused except a single final frame representing an empty line. Complete a chain only on `more == 0`; never expose partial bytes as a Line. Cap raw line bytes at 1 MiB, logical envelope at 4 KiB, fragment count at 64, and total live reassembly allocation per connection at `1 MiB + 4 KiB`; check every limit before append/allocation. Disconnect discards the chain. Future snapshots must define their own typed fragmentation contract before shipping.
- Validate `SessionId` against `[A-Za-z0-9._-]{1,64}`. `SpawnSpec` bounds: 1–128 argv entries, each at most 32 KiB and aggregate at most 128 KiB; at most 128 environment overrides and 128 allow-list names, each name at most 256 bytes, each value at most 32 KiB and aggregate names/values at most 64 KiB; cwd at most 4096 bytes. These are UTF-8 byte limits before platform encoding; forbid embedded NUL, invalid environment names (`=` or empty), disallowed overrides and control payloads above one frame. Before `CreateProcessW`, quote without a shell and reject a command line over 32,767 UTF-16 code units including NUL and an environment block over 32,767 units. Validate before creating a child or reserving live-session ownership.

- Produces `fl_host::serve(config: HostConfig) -> Result<(), HostError>` for the standalone binary and future CLI entry point. The binary handles `--session-supervisor` before normal daemon startup on Unix.
- Child supervision returns a per-session owner handle, bounded stdin writer, stdout reader and stderr reader. The owner retains Unix control/status FDs or Windows Job/process handles, exposes separate `LeaderExited` (exact leader status, once) and `CleanupComplete` notifications, and remains alive after leader exit until cleanup ownership is resolved. Store exact internal signatures in `src/child/mod.rs` before creating either OS implementation.
- Unix daemon reaps only the per-session supervisor. That supervisor is the sole vendor-subtree waiter, sets Linux `PR_SET_CHILD_SUBREAPER` before vendor creation, creates an isolated vendor session and retains subtree ownership after leader exit. Adoption is guaranteed only on Linux within v4.5 §D's limits; macOS has no subreaper. No process-wide `waitpid(-1)` loop belongs in the main daemon.
- Each Unix owner retains a daemon-exclusive control-pipe writer or socket endpoint and a status reader. Control EOF requests bounded TERM-to-KILL cleanup by the supervisor; EOF is never proof that the subtree exited. Close all control/status copies in vendors and helpers, and all unrelated copies in sibling supervisors. Each supervisor closes every control-writer copy and keeps only its intended control-reader/status-writer endpoints; set `FD_CLOEXEC` wherever compatible with that handoff. The supervisor survives leader exit and reports cleanup separately; timeouts or unprovable survivors preserve the record and alert.
- `src/survivor_registry.rs` owns the endpoint-derived state file from Task 1, replacing v2 §3's fixed registry path while preserving v4.5 §D's best-effort limits. Persist session/epoch ownership, supervisor and vendor PIDs, process groups and their start-time identity guards on spawn and exit. A leader exit updates status; it never by itself removes the cleanup owner or its record. Remove an entry only after its recorded cleanup ownership is resolved. Apply Task 1's private owner/mode/no-symlink checks to durable and temporary files, and the current-SID-only creation ACL on Windows.
- On all three platforms, the same module persists a per-session `session_epoch` high-water mark before releasing a spawned child or acknowledging spawn. Retain that mark after cleanup records are retired, and allocate only strictly newer epochs after daemon restart; refuse corrupt state or counter exhaustion rather than resetting an epoch. Persist the epoch and, on Unix, its survivor identity together before execution is released. This prevents a respawn from accepting an old controller's writes under a reused epoch (v4.5 §A).
- Under Task 1's exclusive daemon lock, recover the registry and finish bounded cleanup of provably owned survivors before admitting new sessions. On Linux, acquire stable pidfds first, then validate durable identity against `/proc/<pid>/stat` while the handle's identity remains pinned; refuse any target whose ownership cannot be proven. A start-time check followed by a numeric PID kill is forbidden. Invalid or unresolved identities retain an actionable cleanup alert and cause bounded startup refusal rather than a guessed kill.
- Linux retains pidfds acquired while each live identity is pinned or its child remains unreaped, and signals individual processes only with `pidfd_send_signal`. Define `check_pidfd_support` to probe pidfd availability/permission and return a typed containment refusal when unavailable or disallowed; do not fall back to numeric PID signalling. Serialize signalling and reaping. Numeric process-group signals are allowed only while a retained owner or an unreaped group leader anchors that exact group identity; never signal a saved/reaped PGID. On macOS, `proc_pidinfo` supports identity validation but does not close the check-to-kill race: signal only pinned owned children or anchored owned groups; detached/reparented targets that cannot be pinned retain the documented best-effort residual and refusal.
- Unix spawn has an explicit publication handshake: keep vendor execution gated until a complete supervisor/vendor/group identity record is durably published, then release execution. Acknowledge spawn only after successful Linux subreaper/Unix session setup, durable publication and an exec-success acknowledgement from the vendor launch path; setup/exec failure returns typed spawn failure and cleans up. Write a private temporary file, sync it, atomically replace the registry and sync its directory; exit/status updates use the same ordering. A lost handshake makes gated children exit and requests bounded supervisor cleanup. Restart never treats temporary, truncated or partially written records as cleanup authority; test crashes on both sides of publication. This registry is host cleanup state, not the later hub SessionController persistence.
- Windows uses `STARTUPINFOEX` with `PROC_THREAD_ATTRIBUTE_JOB_LIST` in `CreateProcessW(CREATE_SUSPENDED | EXTENDED_STARTUPINFO_PRESENT)` so the child is born in the per-session `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job, including if the daemon dies during creation. Verify Job membership before `ResumeThread`; acknowledge spawn only after durable epoch publication, containment and resume succeed. The Job is non-inheritable, `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` permits only intended stdio handles, and no breakaway flags are allowed. Creation/assignment/verification/resume failure terminates and waits for any created child before returning typed spawn failure. Account for Windows argument quoting without a shell.
- Retain the Windows Job after leader exit; collect exact leader status through its process handle and confirm descendant cleanup through stable Job accounting/notifications and retained process handles before `CleanupComplete`. Never infer completion from the leader or a saved PID list. Vendors, helpers and sibling sessions must inherit no Job handles. The daemon backstop Job remains optional, with refused setup logged as in the approved spec.
- The creation-time Job list is a Lead implementation refinement of approved pre-execution Job assignment, closing the daemon-death window before post-creation assignment; the archived source snapshot remains unchanged. Primary references: Linux [`pidfd_send_signal`](https://man7.org/linux/man-pages/man2/pidfd_send_signal.2.html), [`PR_SET_CHILD_SUBREAPER`](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html), and Windows [`UpdateProcThreadAttribute`](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) (`JOB_LIST` and `HANDLE_LIST`).

### Task 3: Daemon inventory, bounded pipe I/O and epoch/lease fencing

**Files:**
- Create: `crates/host/src/daemon.rs`, `src/session.rs`, `src/input.rs`, `src/output.rs`.

**Interfaces:**
- Consumes Task 1's authenticated connection and request/event types plus Task 2's child handle and `serve` entry point.
- Produces the working `fl-host` executable serving `Spawn`, `Kill`, `List`, `Events`, `ClaimLease`, `Send` and `Signal`. `List` exposes lifecycle state (including distinct `LeaderExited` and `CleanupComplete`), orthogonal input state (`Writable`/`Fenced`), epoch, pid, start time, exit status and `consumer_stalled`.
- The daemon publishes `Spawned`, complete stdout `Line`, typed protocol failure and `Exited` events. `Exited` reports the exact leader status once and has a reserved notification slot; it does not release the owner. Publish `CleanupComplete` separately only when Task 2 resolves cleanup ownership. Sessions never share sequence counters, stdin queues, stderr tails or kill targets.
- Full durable-consumer ack/replay is deferred to the next slice. This executable is not connected to hub/wire, and no disconnect is represented as guaranteed delivery. A successful socket write does not prove application consumption; foundation retirement rules below are in-memory flow control, not acknowledgements or durable delivery. A later adapter cannot use it until ack/replay lands.

**Output and subscriber bounds:**
- Read stdout incrementally into a per-session shared backlog capped at 8 MiB of retained raw bytes plus logical envelopes, including the partial line and logical events referenced by subscriber queues or in-flight outbound writes. Charge unique shared event storage once and use bounded references rather than copying full lines per subscriber. Bound event metadata as well: at most 4096 retained logical events per session, with at most 4 KiB envelope per event; stop stdout reads when either budget is full. The 1 MiB line cap is independent; detect overflow with bounded lookahead and fail the session explicitly, never truncate. Stderr drainage remains independent with its 64 KiB tail.
- With no subscribers, newly read/unconsumed stdout stays in that shared backlog; stop reading at the cap, set `consumer_stalled`, and let the child encounter pipe backpressure. Do not discard output because the last subscriber disconnected. A new subscriber may drain this pending in-memory backlog, but there is no public replay cursor or promise for output already written to a prior connection. Pump preexisting pending events incrementally within its queue budgets rather than enqueuing the whole backlog at subscription; preserve per-session epoch/sequence order while admitting live events. Clear `consumer_stalled` only when reads can resume within the budgets.
- Admit at most 16 event subscribers daemon-wide; `Events` filters one session or all current/future admitted sessions. Each has at most 64 queued logical events and 2 MiB of referenced logical bytes, plus one reserved `Exited` notification slot per subscribed session (at most 64 slots, at most 4 KiB each). A still-occupied terminal slot for a respawned id counts as slow-subscriber overflow, never an overwrite. A per-subscriber writer sends complete logical chains in order using Task 1's 5 s per-frame absolute write deadline. Queue overflow or write expiry drops only that subscriber with typed `SlowSubscriber` status if deliverable at a logical-message boundary within the deadline; a partially written frame/chain requires connection close. Never block the session reader, session stdin writer or another subscriber on its network write. Preserve exact leader `Exited` state in inventory even when a disconnected subscriber cannot receive its reserved notification.
- Keep each logical event in shared storage until every subscriber to which it was assigned has completed its socket write or been dropped. If no subscriber accepted the event, keep it pending for a future subscriber; if all assigned subscribers dropped before a complete write, return it to pending storage. Release storage after at least one complete socket write and all other references resolve. A chain partially written to a dropped subscriber is discarded by that client; any later delivery to another subscriber remains complete. These rules bound memory and preserve pending output with no consumers, but cannot guarantee delivery across disconnect/daemon death and do not introduce ack/replay.

**Writer outcomes and lease authority:**
- For each session epoch, maintain a nonzero monotonically increasing u64 lease counter, refusing exhaustion rather than wrapping. No daemon-global counter is needed: authority is the full tuple `(session, durable session_epoch, lease_counter, owning authenticated control connection)`. Validate the complete tuple in the per-session writer/authority actor, using its single ordered state, and never accept a lease from a different session, epoch or connection. Any authenticated same-user client may deliberately claim control, consistent with the tmux-equivalent trust boundary. Reconnect preserves child/epoch but must acquire a new lease.
- One dedicated per-session writer owns the stdin handle and every OS write to completion or settled cancellation, independent of the RPC caller's future. Bound admitted Send work to 64 queued frames and 256 KiB of input including newlines; queue refusal guarantees zero bytes. `Send` accepts one line without embedded LF, appends exactly one LF and replies only after a writer result, never merely on queue admission. All input mutations, claims, disconnect revocations and signals share writer-coordinated authority ordering; control operations have a separate bounded priority path so queued data cannot starve takeover. Admit at most one pending claim per control connection and 32 pending authority operations per session; refuse excess immediately with typed `Busy`.
- `SendOutcome::Written` means every byte including LF reached the child's stdin pipe, not that the child processed it. `NotWritten { reason }` guarantees zero bytes for stale epoch/lease, wrong connection, full queue, fenced state or other proven pre-write refusal. `Ambiguous { reason }` means a partial write or a timeout with uncertain completion. Associate the result with the original request id and never retry automatically. Transport loss before the caller observes a result is ambiguous to the caller, even if the daemon completed the write.
- Bound each active input operation by an absolute 5 s deadline from its first write attempt; progress does not extend it indefinitely. A pending takeover stops selection of old queued writes, invalidates them with `NotWritten`, and has the writer finish or abort its one active operation within that bound. Resolve/cancel and join any pending OS write before installing the next owner and sending a successful ClaimLease acknowledgement. Do not hold an unbounded mutex over I/O or grant a lease by immediate atomic generation bump while the old OS write remains pending. Use cancel-safe write primitives / OS cancellation completion; if completion cannot be proven by the deadline, close stdin and fence the session, fail the claim rather than acknowledging a successful unsafe takeover.
- `ClaimLease` has a 5 s absolute deadline from writer admission, with bounded control work; on success, all preceding-lease writes are completed or settled, no previous-lease bytes can arrive after its acknowledgement, and subsequent writes use the new tuple. Concurrent claims execute in writer admission order and return distinct increasing counters; an earlier successful claimant may already be stale when a later claim succeeds. An expired/failed claim does not publish a usable lease, but any partial-write fence remains. This boundary may wait for bounded active I/O; it is not an immediate takeover promise.
- Disconnect of the owning control connection orders revocation through the same authority path: queued input becomes `NotWritten`, active work is settled within its existing deadline, and a partially written abandoned line fences the session. Cancelling an individual caller future does not cancel/drop the writer's in-flight future. A disconnection can lose the response; it cannot permit that client's queued writes under a later owner's lease.
- After any abandoned partial input (takeover, timeout, disconnect or write error), enter `InputState::Fenced` permanently for that epoch, independently of lifecycle state. Every later Send/future Write returns `NotWritten { reason: SessionFenced }` under every lease; no new lease or reconnect repairs a corrupted stdin stream. A fenced session may still grant a lease for epoch-guarded Signal, and epoch-guarded Kill remains available with optional administrative lease. Only kill/cleanup and respawn with a strictly newer durable epoch restores input. Preserve containment ownership while fenced, including after leader exit.
- Validate `Signal` epoch/lease/connection in the ordered authority path immediately before issuing it to Task 2's stable containment owner. Validate `Kill`'s mandatory expected epoch, and any supplied lease/connection, against that owner before cleanup; refuse stale epochs even for authenticated administrative kills. Claim, signal, kill and respawn must not race a check against a different epoch. Future write/resize operations inherit these guards.
