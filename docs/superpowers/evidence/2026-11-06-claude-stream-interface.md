## Bounds and native blockers

Source evidence is enough to design a bounded consumer, not to adopt the Python SDK transport as a proven bounded controller. Its framer joins text before checking length; character counts are not our UTF-8 byte accounting. Query has a 100-object message queue, pending-control dictionaries and per-request tasks without the host slice's aggregate-byte/admission proof (`query.py 227–239, 406–415`; transport 1103+). A future controller needs its own byte/count/depth/string limits, deadline/cancellation and separately bounded control lane. Oversize CLI records are a possible host 1-MiB-line compatibility seam: current source does not establish that every vendor/tool/partial record fits; refuse/uncertain rather than silently truncate or treat that as tool completion.

The SDK's max_budget_usd option is query-scoped, translated to a CLI flag and documented to stop after crossing the threshold (`types.py 2424–2430`, transport 614). That is not proof of a strict aggregate spend cap across persistent turns, child/subagent/background work, concurrent sessions, billing modes or external tools. Usage telemetry/result counters do not enforce that bound. No bounded automated native experiment is authorized until Lead/Owner allocates an enforceable whole-slice budget, exact model/billing/mode/tools/subagent policy and stop/uncertainty behavior. Do not solve this by permission bypass, unbounded continuation or guessed flag semantics.

## Proposed offline fixtures (not run)

1. Bounded NDJSON parser: split every token/UTF-8 seam, CRLF, multiple records, empty/diagnostic lines, valid no-newline EOF versus truncated tail; exact record-byte cap and cap+1, excessive JSON depth/arrays/strings. No partial application/Ack, no allocation-before-charge.
2. Independent identities: initialize/control response out of order, wrong/duplicate/unknown request IDs, stale host epoch/controller generation, wrong session UUID and background result origin. A fake accepted receipt alone cannot authorize vendor retry or prove real CLI acceptance.
3. Approvals: parallel same-tool requests with different tool_use_id/agent_id, callback cancel before/after human decision, connection/lease replacement during wait, duplicate/late decisions, unknown subtype. Revalidate authority after await; no persistent updatedPermissions unless explicitly separately authorized; deny/error paths cannot become allow.
4. Delivery uncertainty: controller commit before host Ack, Ack reply lost, vendor stdin partial write/host Fenced, late vendor echo/result after timeout. Keep durable applied cursor and semantic request correlation separate; Ack-only retry never re-exposes input.
5. Persistent lifecycle: two synthetic turns, result while background follow-up remains, EOF during approval, bounded interrupt/control timeout, cancellation and stream close. Fake fixtures validate our implementation only.

These gaps are concrete downstream gates, not a reason to reopen accepted surviving-host recovery.
